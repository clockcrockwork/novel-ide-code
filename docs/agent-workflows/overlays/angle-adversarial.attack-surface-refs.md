- **regex / parser 的対象には実行可能な攻撃を必須とする**: 敵対的スイープ（正例/負例の表駆動実行）形式で実際に走らせ、exit code・実出力を所見に添える。**スイープはグリフ/エンコーディング変種を網羅する**（全角/半角・Unicode ダッシュ変種 U+2013/2014/2015・バックスラッシュ区切り・全角ファイル名・空白揺れ 等）。推論による列挙は明白なクラスに偏り、文字クラス/エンコーディング単位の穴を取りこぼす（コーパスベンチ〔PR #433 / `docs/pr-analysis/review-angles-bench-round1.md`、コーパスの出典は PR #396 の実穴台帳〕で、単一ブラインドパスがこれらの変種穴を全滅させたことを実証）
- **同一入力クラスを検証する実装が信頼境界の両側（client / worker）または複数箇所にある場合、受理集合の差分を突き合わせる**: 片側だけが通す入力（片側だけが拒む入力）を具体的に構成して判定する。アンカーは [docs/security/TRUST-BOUNDARY.md](../../security/TRUST-BOUNDARY.md) の「client↔worker 検証ペア」表（関数名が同じでも内部の禁止セグメント判定が異なりうるため、ペアの実装を両方読んで突き合わせる。PR #207 でクライアント/worker の `validateGitHubWritePath` 内部判定の乖離がサブディレクトリ配置バイパスを、PR #321 でクライアント側の認可状態と worker 側チェックの乖離〔検証関数ペア以外の二重実装乖離〕が 403 を生んだ）
- **スクリプト/CI ゲート（shell・grep・正規表現・表パーサ）には故障モード別の fail-open / fail-closed 判定を必須とする**: exit code の意味逆転（grep の no-match=1 と `set -e` の相互作用・複数対象の一部マッチで exit 0）/ 空出力 / 列ずれ・書式逸脱 / パース失敗 の各故障モードについて、ゲートが「通す」か「止める」かを判定して宣言する。**4種以外の故障モード**（ツール不在 exit 127・glob 0件マッチ・タイムアウト等）も検討し、該当なしの場合も「その他: 該当なし」と宣言する（PR #168/#349 で secret 検出時も exit 0・正常系 abort・列ずれによる全行欠落が素通りした）

# スキル設計ルーブリック

`SKILL.md` / agent command / `docs/agent-workflows/*.md` を新規作成・改訂するときの最低限の設計基準。

AIエージェントが「それっぽい完了報告」で作業を閉じないように、各スキルは**作業前に正解の所在を固定し、完了扱いにする条件を明示する**。#351 で `docs/ai/` に導入した ground truth / 必須 artifact / verification gate の姿勢（[docs/ai/README.md](../ai/README.md)）を、個々のスキル正本へ落とし込むためのルーブリック。

---

## 各スキルが持つべき6項目

スキル本文（タイトル直後）に、以下6項目を簡潔なブロックとして置く。詳細は本文・正本docsへ参照リンクで逃がし、入口に詳細を集約しない。

| 項目 | 内容 |
|------|------|
| **Ground truth** | そのスキルで参照すべき正解の所在（Issue / docs / tests / `docs/pr/PR-*.md` / 公式docs / ユーザー承認済み仮仕様）。ground truth がない場合は仮の受け入れ条件を明示する |
| **Entry gate** | 何を確認するまで成果物作成に進んではいけないか |
| **Required artifacts** | 作業前・作業後に必ず出す成果物（リスクモデリング表・変更対象ファイル一覧・対応履歴 等） |
| **Verification gate** | 完了扱いにするために必要なコマンド・チェック。変更種別ごとの正本は [docs/ai/rules/verification-gates.md](../ai/rules/verification-gates.md) |
| **Anti-skip rules** | AIがよく使う省略理由の禁止。共通の禁止理由は [docs/ai/README.md](../ai/README.md)「anti-skip rule」を参照 |
| **Cost note** | この手順を破ると何が壊れるか（後追いレビュー指摘の増加・データ破損・誤 push 等） |

## 適用ガイド

### 既存doc / 新規skillへの書き方

タイトル（`# 〜`）の直後、本文の前に blockquote で6項目ブロックを置く。順序は上表どおり（Ground truth → Cost note）。

```md
# {スキル名}

> **Ground truth:** {正解の所在 / 正本リンク}
> **Entry gate:** {着手前に確認すること}
> **Required artifacts:** {前/後に出す成果物}
> **Verification gate:** {種別別ゲート} → [docs/ai/rules/verification-gates.md]({docs}/ai/rules/verification-gates.md)
> **Anti-skip:** [docs/ai/README.md]({docs}/ai/README.md#anti-skip-rule)「anti-skip rule」を参照
> **Cost note:** {破ると何が壊れるか}

{本文…}
```

`{docs}` は、そのファイルから `docs/` ディレクトリへ辿る相対パスに置き換える（配置場所で階層が変わるため、そのままコピペせずリンク切れを確認する）。

| 配置場所 | `{docs}` |
|---|---|
| `docs/agent-workflows/*.md` | `..` |
| `docs/agent-workflows/review-angles/*.md` | `../..` |
| `docs/ai/**` | 階層に応じて `..` / `../..` |
| `.agents/skills/*/SKILL.md` ・ `.claude/skills/*/SKILL.md` | `../../../docs` |

### ループを含むスキルの追加基準

「問題がなくなるまで繰り返す」「パスするまで再実行する」型の手順を含むスキルは、6項目に加えて以下を満たす。**指示動詞（「戻る」「繰り返す」）だけのループは、1周で打ち切っても成果物に痕跡が残らず、スキップを検出できない**（#392 のセルフレビューで実証: 修正コミット自体が新たな所見を生むため、1周のみのレビューは収束を保証しない）。

- **収束条件を明文化する**: 何をもってループを抜けてよいか（例: 新規所見ゼロ）。「問題なければ終了」のような主観条件にしない。
- **収束の判定者を最終修正の作成者から独立させる**: 修正者自身の再検証は修正時の想定の再列挙にしかならず、最終周の修正が動かした境界は誰にも回収されない（PR #396 で実証。判定者の要件は [pre-commit-review.md](pre-commit-review.md) ステップ6 を正とする）。
- **上限と超過時の挙動を決める**: 無限ループ防止の上限周回数と、超過時の扱い（残所見を列挙してユーザー判断に返す。勝手に完了扱いしない）。
- **周回ごとの記録を Required artifacts に含める**: 1周1行（所見数と対応）＋最終行の収束宣言。実施した証拠が成果物に残らないループは、実施しなくても完了報告が同じ見た目になる。
- **機械検査する artifact は受理文法を閉じる（ブロックリストで自由記述を守らない）**: ゲートが自然言語の自由記述を禁止パターンの列挙で検査すると、境界の穴が原理的に無限に残り、指摘→パッチのもぐら叩きが停止しない（PR #396 で実証: レビュー所見30件超の大半がこのクラス）。機械が読むセル・フィールドは「受理する形式」を先に定義し（例: 件数セルは数字のみ、宣言セルは固定語彙）、文法外は理由メッセージ付きで拒否する。同一クラスの指摘が繰り返されたら、パターン追加ではなく入力空間の再設計（文法の閉鎖・構造化）へ一段上がる。人間向けの説明は機械が読まない場所（別セル・表外の本文）に分離する。

### 判断を記録するスキルの追加基準

機械／人間の判断（対応する・見送る・既判断で閉じる 等）を記録するスキルは、6項目に加えて以下を満たす。**判断は「点」ではなく「前提つきの、失効しうる約束」であり、その効力は結論ではなく理由の前提に紐づく**（PR #396 #36 で実証: 一度「見送り」とした判断が、後続の設計変更で理由の前提が崩れていたのに、既判断メカニズムがそのまま結論を再利用していれば誤判断を永続保護していた）。

- **判断は結論ではなく反証可能な理由前提として残す**: 「見送り／今回対応しない」を記録するときは、依存する外部状態を名指しした前提（理想は失効条件つき）を書く（`前提: X が Y である限り不要 ／ 失効条件: X が変わったら見直す`）。前提のない判断は、いつ無効化されたか追跡できない。書式の正本は [review-pr.md](review-pr.md) ステップ4・8（PR判断ログ）/ [risk-modeling.md](risk-modeling.md)（今回対応しない）/ [evidence-check.md](evidence-check.md)（証拠表の前提列）。
- **同一入力の再指摘には、結論の再利用でなく前提の成立確認を1回挟む**: ただし確認は**1回・1文の成立確認に限定**する。再指摘のたびにフル再審理すると既判断（ループ防止）の意味が消えるため、「1文で成立確認」を可能にするのが前段の記録書式（前提を書いておくこと）。この順序が崩れると機能しない。
- **判断の前提を崩す最大要因は後続の自修正**: ガード・分類器・正規表現の修正は境界を動かし、過去の判断の前提を無自覚に無効化する。修正をランドさせるたびに過去判断の前提失効を後ろ向きに点検する工程を持つ（[review-pr.md](review-pr.md) ステップ6.5。[evidence-check.md](evidence-check.md) の前向きドリフト監査と対）。
- **遡及は前向きルールで吸収する**: 本ルール導入前の前提欄なし記録を一括改訂しない。旧記録を既判断で再利用する時点で前提成立を1文確認し追記する（[docs/ai/rules/docs-maintenance.md](../ai/rules/docs-maintenance.md) の遡及判断フロー）。

### 書くときの原則

- **詳細を入口に集約しない**: 6項目は1〜2行ずつに収め、判断基準・手順の本文は正本docsへリンクする。
- **ground truth を最優先で固定**: 成果物作成より先に「何を正解として扱うか」を書く。正本が無いスキルは仮の受け入れ条件を Entry gate に書く。
- **verification gate は実在コマンドで書く**: 存在しない script 名を書かない（[verification-gates.md](../ai/rules/verification-gates.md) と `package.json` を正とする）。
- **anti-skip は共通正本を参照**: 各 doc で禁止理由を再掲せず、[docs/ai/README.md](../ai/README.md#anti-skip-rule)「anti-skip rule」へリンクする。スキル固有の省略理由がある場合のみ1行追記する。

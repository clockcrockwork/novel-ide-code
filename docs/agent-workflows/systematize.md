# セッション自動化提案（Systematize）

> **Ground truth:** 現在の会話セッション履歴 / 既存の [`scripts/`](../../scripts/) ・ [`docs/agent-workflows/`](./)（重複作成を避ける）
> **Entry gate:** 「将来も繰り返す」と判断できるパターンに絞り、ユーザー承認を得るまで実装に進まない
> **Required artifacts:** 自動化候補表（繰り返しパターン / 提案 / 種別）、承認後の作成物と完了報告
> **Verification gate:** 新規スクリプト/ワークフロー作成時は該当種別のゲート → [docs/ai/rules/verification-gates.md](../ai/rules/verification-gates.md)。新規ワークフロー doc は [skill-design-rubric.md](skill-design-rubric.md) の6項目を付与する
> **Anti-skip:** [docs/ai/README.md](../ai/README.md)「anti-skip rule」を参照。「今回だけの偶発的な繰り返し」を候補に含めない
> **Cost note:** 偶発的な繰り返しまで自動化すると未使用スクリプトが増え、メンテ対象とコンテキストを圧迫する

現在の会話セッションを振り返り、繰り返し実行した操作・コマンド・フローを洗い出して自動化候補を提示する。
承認されたものはスクリプト（`scripts/`）または共通ワークフロー（`docs/agent-workflows/`）として実際に作成する。

## 手順

### 1. パターン収集

会話コンテキストから以下を抽出する：

- **繰り返しコマンド** — 同じ `gh` / `git` / `npm` コマンドを2回以上実行した
- **手動整形・変換** — JSON を手でコピー、ファイルに保存して渡す、列を並び替えるなど
- **定型フロー** — 「A したあと必ず B する」という連鎖操作
- **ボイラープレート** — 毎回同じ引数・フォーマットで書くコマンド

### 2. 候補提示

各候補を以下の表で提示し、ユーザーの承認を得る：

```markdown
## 自動化候補

| # | 繰り返しパターン | 提案 | 種別 |
|---|----------------|------|------|
| 1 | ... | scripts/gh/xxx.sh | スクリプト |
| 2 | ... | docs/agent-workflows/xxx.md | 共通ワークフロー |
```

- 「今回だけの偶発的な繰り返し」は候補に含めない
- 「将来も繰り返す可能性が高い」ものに絞る
- すでにスクリプト/ワークフローが存在する場合は改善提案のみ行う

候補がない場合はそのまま終了してよい（「なし宣言」は不要。候補がある場合のみ提示する）。

### 3. 実装

承認された候補を実装する：

**スクリプト（`scripts/gh/` または `scripts/`）：**
- bash (`.sh`) で作成する（`#!/usr/bin/env bash`, `set -euo pipefail`）
- 先頭にコメントで使用例を記載する
- 引数は `${1:?エラーメッセージ}` パターンで必須チェックする
- JSON処理が必要な場合は `jq` を使用する

**共通ワークフロー（`docs/agent-workflows/`）：**
- 既存ワークフローのフォーマットに合わせる
- 引数を受け取る場合は冒頭に記載する
- 手順は番号付きステップで書く
- 必要に応じて Claude / Codex 側の薄い入口も更新する

### 4. 完了報告

```markdown
## 自動化完了

| 作成物 | パス |
|--------|------|
| スクリプト | scripts/gh/xxx.sh |
| ワークフロー | docs/agent-workflows/xxx.md |

次回から該当するエージェント入口または scripts/gh/xxx.sh で呼び出せます。
```

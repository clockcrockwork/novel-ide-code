# カレンダー・執筆工程・目標配分・通知連携仕様

## 目的

novel-ide のカレンダー機能は、汎用的な予定表ではなく、作品ごとの執筆工程・締切・執筆可能日・目標文字数配分を管理するための機能とする。

本文執筆だけでなく、設定決定、プロット、資料調査、推敲、校正、公開準備などの前後工程を時間軸で扱い、ユーザーが無理なく執筆計画を立てられることを目的とする。

また、通知機能と連携し、締切・執筆開始日・前工程期限・後工程期限などを必要に応じて通知できるようにする。

## 基本方針

- カレンダーは「予定表」ではなく「執筆を進めるための時間管理」として扱う。
- 締切がある作品にも、締切がない趣味執筆にも対応する。
- 日ごとの固定目標文字数を直接設定するのではなく、期間と目標文字数から日割り配分する。
- 「この日は書かない」日を明示できるようにする。
- 今日の目標文字数は表示する。
- 今日の達成率は常時表示しない。
- 達成率は週次または月次で集計する。
- カウントダウンはカレンダー本体ではなく、通知機能または通知系モジュールとの連携対象とする。
- ログヒートマップやグラフは有用だが、サイドバー常設ではなく統計ビューで扱う。

## カレンダーイベント分類

カレンダーに登録できるイベントは、最低限以下の分類を持つ。

### 締め切り

作品や作業の最終期限を表す。

例:

- コンテスト締切
- 納品日
- 公開日
- 入稿日

### 執筆期間

本文執筆の開始・終了期間を表す。

例:

- 執筆開始
- 執筆終了

### 執筆前工程

本文を書き始める前に必要な工程を表す。

例:

- 設定決定
- プロット作成
- 資料調査
- 構成確定
- キャラクター設定確定

「これが決まらなければ書き始められない」「ここまでに設定を決め切らないと本文が間に合わない」といった前提条件を管理するために使用する。

### 執筆後工程

本文を書き終えた後の工程を表す。

例:

- 推敲
- 校正
- 誤字脱字確認
- 入稿準備
- 公開準備
- 表紙・概要文・タグ確認

## 色分け

イベント分類ごとに色セットを持つ。

例:

- 締め切り: deadline color
- 執筆期間: writing color
- 執筆前工程: pre-writing color
- 執筆後工程: post-writing color

色は分類単位で設定し、イベントごとの個別色変更は初期段階では必須にしない。

## 締切なし利用への対応

ユーザーによっては、ゴールや締切を設定せず、趣味で好きな時に書く場合がある。

そのため、以下を許容する。

- 締切未設定
- 目標文字数未設定
- 執筆期間未設定
- カレンダーイベントなし
- 通知なし

カレンダー機能を使わなくても、novel-ide の本文執筆機能は成立すること。

## 目標文字数配分

日ごとの目標文字数を直接設定するのではなく、以下の情報から自動算出する。

- 対象作品
- 対象チャプターまたは対象範囲
- 開始日
- 終了日
- 目標文字数
- 書かない日
- 任意の調整日
- メモ/TODO

### 計算ルール

- 対象期間内の日数を取得する。
- 「この日は書かない」と指定された日は配分対象から除外する。
- 配分対象日のみに目標文字数を割り当てる。
- 除外日は目標文字数を 0 として扱う。
- 端数が出る場合は、最終日または先頭日から調整する。
- 手動調整された日の目標文字数は固定値として扱い、残り文字数を残りの日数へ再配分する。

### データ例

```ts
type WritingGoalPlan = {
  id: string;
  workId: string;
  chapterId?: string;
  title: string;
  startDate: string;
  endDate: string;
  targetCharacters: number;
  excludedDates: string[];
  fixedDailyTargets?: {
    date: string;
    targetCharacters: number;
  }[];
};
```

## 「この日は書かない」指定

カレンダー上で、特定の日を「書かない日」として指定できる。

用途:

- 予定がある
- 体調を考慮する
- 仕事が忙しい
- 移動日
- 休息日
- 別作品の作業日

「書かない日」は目標文字数配分から除外する。

ただし、その日に実際に執筆した場合は、実績として記録してよい。

## TODO・予定との関係

カレンダーには、執筆目標だけでなく、予定や TODO も登録できるようにする。

例:

- この日は書かない
- 設定を決める
- プロットを整理する
- キャラクター表を更新する
- 校正する
- 入稿する
- 公開準備をする

TODO は通知対象にできるが、必ずしも目標文字数配分に影響しない。

## 今日の表示

今日のサイドバー表示では、以下を軽量に表示する。

- 今日の目標文字数
- 今日の予定/TODO
- 直近の締切
- 今執筆中の作品リンク
- 週次または月次の進捗バー

以下は常設表示しない。

- 今日の達成率
- 最近触っていない作品
- 常時カウントダウン
- ログヒートマップ
- 詳細グラフ

## 達成率表示

達成率は数値を常時表示せず、バー表示を基本とする。

対象:

- 週次達成率
- 月次達成率
- 目標期間全体の進捗率

バーをクリックまたはタップした場合に、詳細数値を表示する。

表示例:

- 実績文字数
- 目標文字数
- 差分
- 達成率
- 残り必要文字数

## 通知機能との連携

カレンダーイベント、目標文字数配分、TODO は通知機能と連携できるようにする。

通知対象の例:

- 締切前通知
- 執筆開始日通知
- 執筆終了予定日通知
- 執筆前工程の期限通知
- 執筆後工程の期限通知
- 今日の予定/TODO 通知
- 書かない日の確認通知
- 週次/月次の進捗確認通知

### 通知責務

カレンダー本体は、通知の発火条件に必要な情報を提供する。

実際の通知表示・通知チャネル選択・通知頻度管理は通知機能側の責務とする。

通知チャネル例:

- アプリ内通知
- Web Push
- Discord 通知
- 将来的な外部連携通知

### カウントダウンの扱い

カウントダウンはカレンダー本体の常設表示にはしない。

必要な場合は、通知機能または通知系サイドバーモジュールで扱う。

例:

- 締切 3 日前
- 締切前日
- 締切当日
- 執筆開始予定日
- 前工程期限前日

## ログ・ヒートマップ・グラフ

ログヒートマップやグラフは、執筆継続支援として有用なため将来的に実装対象とする。

ただし、サイドバー常設ではなく、進捗/統計ビューで扱う。

対象データ:

- 日別文字数
- 週別文字数
- 月別文字数
- 作業時間
- 執筆日数
- 連続執筆日数
- 作品別進捗
- 目標との差分
- 執筆の波

## サイドバーモジュールとの関係

カレンダー情報は、サイドバーモジュールとして一部を表示できるようにする。

ただし、サイドバーは軽量表示に限定する。

表示候補:

- 今日の目標文字数
- 今日の TODO
- 直近の締切
- 今執筆中の作品リンク
- 週次/月次進捗バー

詳細なカレンダー操作、目標配分編集、グラフ確認は専用ビューで行う。

## 今執筆中の作品リンク

サイドバーには、現在執筆中の作品へのリンク一覧を表示できるようにする。

対象例:

- 進行中フラグがある作品
- 現在の目標文字数配分に含まれる作品
- 直近のカレンダーイベントに紐づく作品
- ユーザーがピン留めした作品

「最近触っていない作品」は表示しない。

理由:

- 完了フラグがないだけの作品を不要に掘り起こす可能性がある。
- クライアント都合や外部要因で状態変更できない作品がある。
- ユーザーの心理的負荷が高くなる可能性がある。

## MVP 範囲

初期実装では、以下を優先する。

- イベント分類
- 作品へのイベント紐づけ
- 締切日
- 執筆期間
- 執筆前工程
- 執筆後工程
- 「この日は書かない」指定
- 期間と目標文字数からの日割り計算
- 今日の目標文字数表示
- 週次/月次進捗バー
- 通知機能へ渡すためのイベント情報定義

## MVP 外

以下は初期実装では必須にしない。

- Google Calendar 風の汎用予定表
- 外部カレンダー同期
- 詳細な日別達成率表示
- 今日の達成率常時表示
- 常時カウントダウン
- ヒートマップ
- 詳細グラフ
- 自動リスケジューリング
- AI による目標再配分

# ドキュメントモード・レビューPR運用 将来設計

> **MVP対象外。** MVP後に設計・実装するための将来設計ドキュメント。
> 関連 issue: [#177](https://github.com/clockcrockwork/novel-ide/issues/177)（具体化）/ [#176](https://github.com/clockcrockwork/novel-ide/issues/176)（基本方針）

---

## 背景と方針

novel-ide は [docs/ARCHITECTURE.md](../ARCHITECTURE.md) の「創作文書管理方針」に従い、本文・設計カード・スタイルリファレンスを Markdown/JSON 等の可読ファイルとして Git 管理する。

このドキュメントは、その方針を具体化する以下の将来機能を整理する。

- ドキュメントモード
- ブロック表示プリセット
- 原稿単位の作業ブランチ運用
- レビューPR運用
- PRレビューコメント連携
- レビューコメント基盤

AIワークフローは具体的な利用シナリオとして記載するが、**AIを使わない場合（校正・手動レビュー・差分確認）でも成立する設計**とする。

---

## 1. ドキュメントモード

本文以外の創作文書を novel-ide 内で編集できるモード。

### 対象文書の例

```
docs/series-overview.md       シリーズ全体ドキュメント
docs/design-cards/E08.md      エピソード設計カード
docs/design-cards/E08-S03.md  シーン/ビート設計カード
docs/style-reference.md       スタイルリファレンス
docs/writing-workflow.md      AIワークフロー定義
docs/forbidden-list.md        禁止事項リスト
docs/continuity-map.md        対比・回収マップ
docs/settings/               設定資料
```

### 扱うブロック

Tiptap ベースで以下を編集可能にする。

- 見出し（h1〜h3）
- 段落・太字・イタリック
- テーブル
- TODOリスト（チェックボックス）
- 通常リスト（箇条書き・番号付き）
- コードブロック
- 引用
- 折りたたみ見出し
- タイムラインブロック（将来）

## 2. ブロック表示プリセット

ドキュメントモード内の Markdown/Tiptap 文書を、用途に応じて読みやすく表示するプリセット。

| プリセット名 | 対象文書 |
|---|---|
| 設計カード表示 | エピソード・シーン設計カード |
| チェックリスト表示 | 完了確認チェックリスト |
| 禁止事項表示 | 禁止事項リスト |
| 前提事実表示 | 作品世界の固定事項 |
| シーン/ビート一覧 | ビート表・シーン一覧 |
| 対比・回収マップ | 伏線・対比・回収の対応表 |
| スタイルリファレンス | 文体・表記の参照資料 |
| タイムライン表示 | 時系列イベント（将来） |

### 方針

- フォーマットを完全固定しない。パース可能な部分だけ便利に扱う。
- パース不能な部分は通常の Markdown 文書として維持する。
- AIワークフロー改善に合わせてフォーマットを変更できるようにする。

---

## 3. AIワークフロー事例

AIを使った創作ワークフローの具体例（AIを使わない場合でも、各フェーズは手動作業・校正・差分確認として成立する）。

```
Phase 1: ネタ合わせ
Phase 2: シリーズ/話ドキュメント作成
Phase 3: エピソード > シーン > ビート単位の設計カード作成
Phase 4: AI草稿（ブランチ: work/episode-E08）
Phase 5: ユーザーによるリライト（差分として記録）
Phase 6: AIチェックリスト差分・校正・レビュー（PRとして管理）
Phase 7: 差分からスタイルリファレンス/禁止事項/設計カード更新
```

---

## 4. 原稿単位の作業ブランチ運用

同一原稿ファイルは同一作業ブランチまたは同一レビュー単位で扱う。

```
main
  └ work/episode-E08
      ├ commit: Phase4 AI草稿
      ├ commit: Phase5 ユーザー修正版
      ├ commit: Phase6 レビュー修正版
      └ commit: Phase7 スタイル抽出・設計カード更新
```

### UI上の抽象化案

Git 用語を過度に露出させず、以下の状態として表現することも検討する。

| UI表示 | Gitの状態 |
|---|---|
| 作業中 | ブランチに未コミット変更あり |
| レビュー中 | PR open |
| 未解決コメントあり | PR に unresolved review comment |
| mainとの差分あり | ブランチが main から diverge |
| マージ待ち | PR approved / merge ready |
| 破棄候補 | ブランチを close/delete 予定 |

---

## 5. レビューPR運用

原稿・設計カード・スタイルリファレンス等の変更を、必要に応じてPRとして管理する。

### レビュー対象

- 誤字脱字
- 表記揺れ
- 文体違反
- 禁止事項違反
- チェックリスト未達
- 設計カードとの差分
- AI草稿 → ユーザー修正版の変化
- スタイルリファレンス候補の抽出

---

## 6. PRレビューコメント連携

| 状態 | 動作 |
|---|---|
| GitHub PRが存在する | novel-ide 内のレビューコメントを GitHub PR レビューコメントと同期/参照できる |
| GitHub PRが存在しない | novel-ide 内のローカルレビューコメントとして成立する |

- レビューコメントは本文範囲・差分・チェックリスト項目・設計カード項目と関連付けられる
- `resolved` / `unresolved` を扱えるようにする

---

## 7. レビューコメント基盤

AI専用ではなく、広義のレビューコメント基盤として設計する。

```ts
type ReviewSource =
  | "manual"           // 手動レビュー
  | "proofreading"     // 校正エンジン
  | "formatter"        // 自動整形
  | "style-check"      // スタイルリファレンス照合
  | "ai-review"        // AIレビュー
  | "checklist-review" // チェックリスト差分

type ReviewCommentType =
  | "typo"           // 誤字脱字
  | "format"         // 表記・書式
  | "style"          // 文体違反
  | "checklist-miss" // チェックリスト未達
  | "forbidden"      // 禁止事項違反
  | "continuity"     // 連続性・伏線
  | "suggestion"     // 提案（変更を強制しない）
```

### 保存形式

レビューコメントの取り込みは**手動のみ**（自動取り込みなし）。novel-ide プレビューモードのコメント・マーカーと同一データ形式で保存する。

| ユーザー種別 | 正 | キャッシュ | 管理情報 |
|---|---|---|---|
| **Git 利用ユーザー** | GitHub PR レビューコメント | IndexedDB（都度同期・都度破棄） | IndexedDB に `lastSyncedCommentId` を保持 |
| **非 Git ユーザー** | IndexedDB | — | IndexedDB のみで resolved/unresolved を管理 |

Git ファイル（`reviews/*.review.json` 等）としてレビューコメントを管理**しない**。頻繁な更新が Git diff のノイズになり、コンフリクトが多発するため。PR レビューコメント側を正とし、IndexedDB を同期キャッシュとして扱う設計とする。

# モバイル手動確認手順

Playwright WebKit emulation では実機 iOS キーボードの完全再現は不可能なため、以下の手順で実機確認を行う。

## 確認環境

| 環境 | 優先度 |
|------|--------|
| iPhone Safari | 最優先 |
| iPhone PWA (ホーム画面追加) | 最優先 |
| iPad Safari | 推奨 |
| Android Chrome | 推奨 |

## 確認手順

### 1. キーボード表示時のレイアウト

1. 執筆画面を開く
2. 本文エリアをタップしてキーボードを表示
3. 確認：
   - footer（モード切替・フォーマットボタン）がキーボードの上に表示される
   - footer がキーボードの裏に隠れない
   - header が画面外に消えない
   - body/ページ全体がスクロールしていない（`window.scrollY === 0`）

### 2. キーボード表示中のスクロール

1. 長文（2,000字以上）を用意する
2. 本文エリアをタップしてキーボードを表示
3. 本文を上下にスクロールする
4. 確認：
   - footer がスクロールに巻き込まれて消えない
   - footer 内のボタンがタップ可能
   - header が消えない
   - ページ全体ではなく本文エリアのみスクロールしている

### 3. フォーカス時の挙動

1. 長文の途中の行にカーソルを置く
2. 一度他をタップしてフォーカスを外す
3. 再度同じ行をタップしてフォーカス
4. 確認：
   - キーボード表示後にアプリ全体が画面外にずれない
   - カーソル行がキーボード / footer に隠れない
   - header / footer が置き去りにならない

### 4. 日本語フリック入力

1. 本文エリアをタップ
2. フリック入力で日本語を入力する
3. 変換候補を選択する
4. 確認：
   - 変換中に footer / toolbar がジャンプしない
   - 変換確定後もレイアウトが崩れない
   - スクロールが暴走しない

### 5. 横画面（landscape）での動作

1. portrait でキーボードを表示した状態にする
2. デバイスを横向きに回転させる
3. portrait に戻す
4. 確認：
   - 回転後も footer が画面内に収まる
   - editor 本文エリアが操作可能
   - `--footer-cover` が適切な値に更新される

### 6. ルビ・ポップアップとキーボードの共存

1. テキストを選択してルビ編集ポップアップを開く
2. キーボードを表示した状態でポップアップを操作する
3. 確認：
   - ポップアップが viewport 内に表示される
   - キーボードの裏に隠れない
   - スクロールしてもポップアップが追従または閉じる

### 7. 空・短文ファイルでの下部タップ → 末尾カーソル（手が小さいユーザー向け）

1. 新規ファイルを作成する（本文が空、または 1〜2 行だけの状態）
2. 執筆画面でメインエリアの**下部 1/3 付近の余白**をタップする
3. 確認：
   - キャレットが本文末尾（最終行の末尾）に入る
   - キーボードが表示され、キャレットがキーボード直上に見える位置までスクロールする
   - 本文がほとんど無くても、画面下部のタップで確実に入力を開始できる
4. 本文を数行入力した後、最終行より下の余白を再度タップしても末尾に入ることを確認する

### 8. Android Chrome のキーボード追従（interactive-widget）

1. Android Chrome で執筆画面を開く
2. 本文エリアをタップしてキーボードを表示
3. 確認：
   - footer がキーボード直上に出る（`interactive-widget=resizes-content` でレイアウトビューポートが縮む）
   - iOS 同様、スクロール・フォーカス移動中も footer 位置がビュー基準で固定
   - footer が二重にずれる（過補正で浮く）等の不具合がない

### 9. PWA standalone モード固有確認

1. ホーム画面から PWA を起動する
2. 上記 1〜8 の手順を繰り返す
3. 追加確認：
   - safe-area（ノッチ・Dynamic Island・ホームインジケーター）に UI が被らない
   - ホームインジケーター領域に footer ボタンが被らない

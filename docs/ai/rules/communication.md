# 対話・文書の簡潔化規則

エージェントの出力（ユーザーとの対話・issue 本文・PR 本文・恒久 docs）を簡潔に保つための正本。
PR 本文テンプレの正本は [create-pr.md](../../agent-workflows/create-pr.md)、issue 承認フローの正本は [REVIEW_GUIDELINES.md「issue の作成・close」](../../REVIEW_GUIDELINES.md#issue-の作成close承認フロー正本)。

## ユーザーとの対話

伝える優先順:

1. 結論
2. 現在地（いま何がどこまで済んでいるか）
3. 判断事項（ユーザーに委ねる判断）
4. 根拠（判断に必要な分のみ）
5. 次の行動

削減対象（書かない）:

- 既知の前提の全文再掲
- ツール操作の実況
- 同じ結論の繰り返し
- 判断に不要な網羅列挙
- 求められていない将来構想
- 既に回答済みの質問の再確認

## issue 本文

基本構成: **問題 / 目的 / 現状 / 対応範囲 / 非目的 / 完了条件 / 依存関係**。

調査ログ・会話履歴・検討経緯の大量転記はしない（必要なら PR・commit・会話へのリンクで示す）。

## PR 本文

基本構成: **提供結果（必要な理由を含む）/ 最終的な変更 / 検証セクション（完了条件・想定ケース・既存実装調査・証拠表・レビューループ記録 — 見出し名は機械ゲートが検査するため変えない）/ 残る制約・判断 / closes・refs**（テンプレ・機械ゲート要件は [create-pr.md](../../agent-workflows/create-pr.md)）。

削減対象: commit ごとの作業日誌、全レビューコメントの再掲、恒久 docs の本文複製。

## 恒久 docs

残すもの:

- 現在有効な規則
- 実行手順
- 判断基準
- 例外
- 復旧方法
- 正本へのリンク

削減するもの（既存 docs への遡及適用は減算 Phase で行う。新規作成・改訂時は最初から書かない）:

- 旧案との比較・検討経緯
- PR 固有の経緯
- 完了済み移行の説明
- 将来候補の網羅一覧
- 他 docs との重複（リンク参照に置き換える）
- 実装から機械的に取得できる一覧
- 暫定規則（恒久 docs に書かず、期限・撤回条件付きの計画文書に置く）

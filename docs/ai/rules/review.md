# PRレビュー — 遡及チェック・競合確認

PRレビュー時に「後から追加されたルールとの差分」を確認するための手順。
コーディング規約・セルフレビュー項目・禁止事項の詳細は [docs/REVIEW_GUIDELINES.md](../../REVIEW_GUIDELINES.md) を参照する。

---

## 遡及チェック

PR が作成された後にルールが追加・変更されていないかを確認する。

### 確認手順

1. **ルール更新履歴を確認する**

   ```bash
   git log --oneline -- docs/ai/ docs/REVIEW_GUIDELINES.md docs/agent-workflows/ \
       docs/data-model/INVARIANTS.md docs/security/ docs/maintenance/ | head -20
   ```

   PR 作成日より新しいコミットがある場合、その変更内容を確認する。

2. **追加されたルールがこの PR に適用されるか判断する**

   | 状況 | 対応 |
   |------|------|
   | PR 作成後に追加されたルールがあり、今回の変更に該当する | 対応を検討し、PR 本文または Issue に記録する |
   | PR 作成後に追加されたルールがあるが、今回の変更には非該当 | 記録不要。スキップしてよい |
   | ルール変更がない | チェック完了 |

3. **REVIEW_GUIDELINES.md の新しい節を確認する**

   特に以下の節が追加・変更されていないか確認する：
   - 「テスト必須カテゴリ」（テスト追加要否に影響する）
   - 「セキュリティレビュー」（脆弱性チェック観点の追加）
   - 「レビュー観点チェックリスト」（新項目の追加）

## 既存 Issue / PR との競合確認

### 確認手順

1. **同一ファイルを変更する未完了 Issue・PR を検索する**

   GitHub 上で変更対象ファイルを含む open Issue / open PR を確認する。
   （gh CLI が使える場合: `gh issue list --state open`、`gh pr list --state open`）

2. **実装方針の矛盾を確認する**

   | 状況 | 対応 |
   |------|------|
   | 同一ファイルを別 Issue が変更予定で、方針が矛盾する | 両 Issue を担当者・作成者に確認し、調整する |
   | 同一ファイルを変更する open PR があり、コンフリクトが予想される | PR 本文に記載し、マージ順序を調整する |
   | 競合なし | チェック完了 |

---

## レビュー時の判断フロー

遡及チェック・競合確認の結果に応じて対応を判断する。

```
遡及チェック完了
  └─ 新ルールが今回の PR に適用されるか？
       ├─ 適用される → 対応（または明示的に見送り理由を PR 本文に記載）
       └─ 適用されない → スキップ

競合確認完了
  └─ 競合する Issue / PR があるか？
       ├─ ある → 調整してから実装・マージ
       └─ ない → レビュー継続
```

各コメントへの対応可否（対応する / 見送る / 要確認）の詳細な判断基準は
[docs/REVIEW_GUIDELINES.md — PRレビュー対応](../../REVIEW_GUIDELINES.md) を参照する。

---

## チェックリスト（レビュー開始時）

```
[ ] PR 作成日より後にルールの更新がないか確認した
[ ] 追加されたルールが今回の変更に該当するか判断した
[ ] 同一ファイルを変更する競合 Issue / PR がないか確認した
[ ] 競合がある場合、調整方針を PR 本文に記載した
```

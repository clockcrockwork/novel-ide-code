# 本文チェック方針（issue #256）

> 後続の本文チェック実装 issue から参照するための用語定義・設計方針ドキュメント。
> MVP 段階定義の正は [docs/MVP_PLAN.md](../MVP_PLAN.md) であり、本書はその補足として読む。

---

## 設計思想

novel-ide の正本は、エディタ表示結果ではなく、ユーザーの Git/ローカルに保存されるテキストファイルである。

そのため、本文品質に関わるチェックは、CSS やレンダリングによる見た目の補正ではなく、
正本テキストに対する検出・警告として扱う。

- **CSS/render による表示補正**：ルビ・禁則・字詰め等の「読みやすさ」をレンダリング時に補正する。正本テキストは変更しない。
- **正本テキストへのチェック**：スタイルルールや校正指摘を正本テキストに対して実行し、警告・提案として返す。レンダリングとは独立して動作する。

この分離により、外部ツール（VSCode・GitHub・Obsidian 等）から正本を読んだ場合でも、
novel-ide 固有の表示補正に依存しない本文品質を維持できる。

---

## 用語定義

### スタイルルール

表記・記法・禁則・文体に関する **Lint 系チェック**を指す。

- 対象：空白の使い方・全角/半角・句読点の統一・特定表記の禁止など
- 性質：誤りの断定ではなく、原則として**警告・提案に留める**
- 実行タイミング：テキスト変更時（debounce）または手動トリガー
- 実装場所：`src/lib/writingRules.js`（テキスト変換）、`src/lib/tiptap/WritingRulesExtension.js`（エディタ統合）および将来の Lint ルールエンジン

### 校正

誤字・脱字・衍字・誤変換など、**本文内容の誤り検出**を指す。

- 対象：読み誤り・変換ミス・重複語・固有名詞の揺れなど
- 性質：辞書・外部 API・LLM を組み合わせる高度な処理
- 実行タイミング：手動トリガーまたは保存時（非同期キュー）
- 設計詳細：[docs/proofread/](../proofread/README.md)

## MVP スコープ対応表

| 段階 | スタイルルール | 校正（誤字脱字衍字・誤変換） |
|------|--------------|--------------------------|
| **Alpha** | 対象（既存 `writingRules.js` および Lint 系） | **対象外** |
| **Beta** | 継続・拡張 | 辞書生成・ユーザー辞書・ローカル校正 |
| **Gamma** | 継続・拡張 | 外部 API 校正（Yahoo・Gemini 等） |
| **Delta 以降** | 継続・拡張 | LLM 校正・文脈校正・矛盾検知 |

「校正なし」（MVP_PLAN.md Alpha 定義）は、誤字脱字衍字・誤変換検出を行わないという意味であり、
スタイルルールチェック（Lint 系）を排除するものではない。

## CSS/render 補正と正本チェックの分離

| 区分 | 例 | 正本テキストの変化 | 実装場所 |
|------|----|--------------------|---------|
| CSS/render 補正 | ルビ表示・禁則処理・字詰め | **なし** | CSS / TipTap ノード属性 |
| スタイルルールチェック | 全角スペース警告・表記ゆれ検出 | なし（警告のみ） | `writingRules.js` / Lint エンジン |
| スタイルルール適用 | 自動変換（入力時の文字置換） | **あり**（ユーザー同意のもとで） | `writingRules.js` |
| 校正（Beta 以降） | 誤字・脱字・衍字指摘 | なし（提案のみ） | [docs/proofread/](../proofread/README.md) 設計参照 |

自動変換（スタイルルール適用）は正本テキストを書き換えるため、ユーザーが明示的に有効化した
ルールのみ実行し、変換内容はエディタの undo 履歴に残す。

## 本文チェック UI 方針（MVP-alpha）

### 基本 UI

MVP-alpha の本文チェック（スタイルルール）は以下の UI を基本とする。

- **エディタ内**：チェック対象箇所を**背景色マーカー（ハイライト）**で示す
  - アンダーバー（下線）・波線・常時下線表示は MVP-alpha では採用しない
- **サイドバー**：チェック結果を「本文チェック」モジュール（`WritingCheckMod`）として一覧表示する
  - 既存の `RulesMod`（執筆ルール・自動変換）とは別の新規モジュールとして実装する
- **ジャンプ**：サイドバーの項目クリックでエディタ内の該当箇所へスクロール・フォーカスする

```txt
本文チェック
├─ 表記: 三点リーダの形式が揺れています
├─ 記法: ルビ記法が閉じられていません
├─ 禁則: 行頭に閉じ括弧があります
└─ 文体: 一文が長い可能性があります
```

### severity（深刻度）

文体チェックは小説の演出・キャラクター口調と衝突しやすいため、`error` として扱わない。

| チェック種別 | severity |
|------------|----------|
| 表記チェック | `warn` |
| 記法チェック | `warn` |
| 禁則チェック | `warn` |
| 文体チェック | `suggestion` |

スタイルルールチェックは原則として `warn` または `suggestion` に留め、`error` は使用しない。

### スタイルルールチェックと校正（Beta+）の UI 差分

両者はいずれも背景色マーカー方式を採用するが、サイドバーモジュール・マーカー色・操作セット（置換・無視）が分離される。

| 区分 | MVP 段階 | エディタ表示 | サイドバー | severity |
|------|---------|------------|-----------|----------|
| スタイルルールチェック（表記・記法・禁則・文体） | **Alpha** | 背景色マーカー | WritingCheckMod（ジャンプリスト） | warn / suggestion |
| 校正（誤字・脱字・衍字・誤変換） | **Beta 以降** | 背景色マーカー（別色） | ProofreadMod（ジャンプ・置換・無視） | error / warn / info / suggestion |

校正の詳細 UI 設計（色定義・ProofreadExtension）は [docs/proofread/SOURCES.md](../proofread/SOURCES.md) を参照。

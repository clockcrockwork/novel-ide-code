# VirtualList Benchmark

`bench/` は `src/components/common/VirtualList.jsx` の描画性能を確認するためのベンチマークアプリです。パフォーマンス基盤整備（#23）と、仮想化関連 issue の before/after 計測に使用します。

## 起動方法

```bash
npm run bench
```

上記は `vite bench/` を実行します。ブラウザで表示されたローカル URL を開き、画面上部の数値と Chrome DevTools の計測結果を記録してください。
Windows PowerShell で `npm.ps1` の実行がブロックされる場合は、代わりに `npm.cmd run bench` を使用してください。

## 現在の計測対象

現行のベンチアプリは、10,000 行の可変高さリストを `VirtualList` で表示します。

- 初期描画時間: モジュールロードから最初の `requestAnimationFrame` 完了までの時間
- スクロール FPS: `VirtualList` の ref 経由で `scrollTo` しながら 120 フレーム分を計測した avg/min FPS
- 可変高さ行: 短い行、長めの行、補足テキスト付き行を混在させたリスト
- 対象コンポーネント: `src/components/common/VirtualList.jsx`

WriteMode（TipTap / ProseMirror）への仮想化は対象外です。ProseMirror の position-based tree と非互換なため、読み取り専用リストだけを対象にします。

## 想定データ量

小説 IDE の実利用では、行数だけでなく文字数と 1 行あたりの文字数も負荷に影響します。before/after を記録するときは、少なくとも次の観点を分けて扱ってください。

- 行数: 10,000 行だけでなく、最大 50,000 行程度までを想定する
- 総文字数: 500,000 字程度の原稿を想定する
- 長い 1 行: 行数が少なくても、1 行の文字数が多いケースではレイアウト計算や高さ測定が重くなる
- 可変高さ: 短い行と長い行が混在するケースでは、スクロール中の再測定コストに注意する

現行の `bench/main.jsx` は固定の 10,000 行データだけを生成するため、50,000 行、500,000 字、長い 1 行を切り替えて測るにはベンチアプリ側の拡張が必要です。この README は現行ベンチの使い方を文書化し、追加シナリオの整備は #81 で追跡します。

現行データは `Math.random()` を使って行の長さを生成するため、リロードごとに総文字数や最長行が変わります。before/after は同じ端末・ブラウザで複数回計測し、中央値などの代表値で比較してください。シード固定や決定的なデータ生成は #81 で整備します。

## Chrome DevTools での計測手順

1. `npm run bench` でベンチアプリを起動する。
2. Chrome でベンチアプリを開く。
3. DevTools を開き、Performance タブを選ぶ。
4. Reload を含めて計測する場合は、Performance タブの録画開始後にページを再読み込みする。
5. スクロール性能を計測する場合は、録画中に `FPS 計測開始` を押す。
6. `計測中…` 表示が終わったら録画を停止する。
7. Summary、Main、Frames、FPS、Long task を確認する。

画面上の `初期描画` と `スクロール FPS (avg/min)` は簡易指標です。PR や issue に貼る数値は、可能なら DevTools の記録と併記してください。
